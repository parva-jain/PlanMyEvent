# 004. Cloudflare R2 for file storage

- Status: Accepted
- Date: 2026-10-02

## Context

The app stores gallery photos, receipts and cover images. Estimates put year-one storage around 150 GB, but gallery viewing could reach about 9 TB of downloads a year, since hundreds of guests view each event's photos. Bandwidth, not storage, is the cost that grows.

## Decision

Use **Cloudflare R2** through the standard AWS S3 SDK. Gallery images are served from a public bucket behind Cloudflare's CDN; receipts sit in a private bucket and are served through short-lived signed URLs. Locally, MinIO stands in for R2.

## Rationale

- R2 charges no bandwidth (egress) fees; S3 charges per GB served.
- R2 has an ongoing free allowance; S3's free tier is mostly limited to the first year.
- R2 uses the S3 API, so switching to S3 later is a configuration change.

## Consequences

- No Mumbai-specific region choice as with S3; acceptable since there is no strict data-residency requirement.
- Fewer ecosystem features than S3 (event triggers, lifecycle rules); thumbnails are generated by our own worker instead.
- Uploads go directly from the browser to R2 with presigned URLs, so the API never handles file bytes.
